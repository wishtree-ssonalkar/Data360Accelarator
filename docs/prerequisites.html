Prerequisite checklist

People

RoleNeeds
Business usersA modern browser (Chrome, Edge, Firefox, Safari) and the app's URL. Nothing to install.
Admin (onboards clients and sources)The admin password. Basic understanding of the client's systems and data.
IT / DevOps (installs and runs it)A server or VM with Docker, or a machine with Python; access to the client's network and sources.

Software

WhereRequiredNotes
Server (recommended)Linux VM with Docker 24+ and Docker Compose v2Everything else, including the SQL Server ODBC driver, is inside the image.
Laptop / without DockerPython 3.13, GitWindows, macOS or Linux.
Database sources (non-Docker)The database's ODBC driver (e.g. "ODBC Driver 18 for SQL Server", Oracle Instant Client ODBC)Only for SQL Server, Oracle or other ODBC sources. PostgreSQL, MySQL and SQLite need no driver.

Keys and secrets

ItemRequired?How to get it
CDP_ADMIN_PASSWORDProductionChoose a strong password. Protects the admin screens.
CDP_SECRET_KEYProductionRun python -m cdp secret-key (or docker compose run --rm cli secret-key). Keep a safe copy: stored credentials cannot be read without it.
An AI provider keyOptionalAny one of: Anthropic Claude, Google Gemini, OpenAI, Azure OpenAI, or an OpenAI-compatible service (Groq, Mistral, OpenRouter, local Ollama). Entered in the app under Admin → AI assistant. Without it, "Ask your data" runs its built-in example questions only.

What to get from the client

  • List of systems that hold customer data (store, CRM, POS, helpdesk, website analytics, loyalty, ERP) and an owner for each.
  • Access to each (read-only is enough):
    • Files: exports (CSV/Excel/JSON/Parquet), or a storage location (S3 bucket, Azure container, SFTP drop) with read credentials.
    • Databases: host, port, database name, a read-only user, and the tables or a query; firewall opened to the WishUnify server.
    • APIs: base URL, a token with read scope, and the API documentation (paging, rate limits).
  • A small sample (a few hundred rows) of each source, to build and test mappings.
  • Business definitions: what "active" means (e.g. bought within 6 months), churn thresholds, tier spend limits, which source is the most trusted for names and contact details.
  • Data-protection approval for processing personal data (names, emails, phones) and, if the AI assistant is used, for sending aggregated results to the AI provider.

See Data requirements for exactly which fields are needed.

Install on a laptop (demo)

  1. Get the code 
    git clone https://github.com/wishtree-ssonalkar/Data360Accelarator.git
cd Data360Accelarator
  2. Create a virtual environment and install 
    python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt      # Windows
# .venv/bin/python -m pip install -r requirements-dev.txt        # macOS / Linux
  3. Check the configuration 
    .venv\Scripts\python -m cdp validate
  4. Create the sample data and load it 
    .venv\Scripts\python -m cdp sample-data
.venv\Scripts\python -m cdp run
    This takes about 10 seconds and prints each source and model it builds.
  5. (Optional) Enable the AI assistantAfter starting the app, open Admin → AI assistant, choose your provider (Claude, Gemini, OpenAI, Azure OpenAI or OpenAI-compatible), enter the model and API key, click Test connection, then Save. (Setting ANTHROPIC_API_KEY, GEMINI_API_KEY or OPENAI_API_KEY as an environment variable also works.)
  6. Start the app 
    .venv\Scripts\streamlit run app\streamlit_app.py
    Open http://localhost:8501. On a laptop without CDP_ADMIN_PASSWORD, the admin screens open with a warning banner.
  7. (Optional) Run the tests 
    .venv\Scripts\python -m pytest -q

Deploy on a server (Docker)

  1. Get the code on the server 
    git clone https://github.com/wishtree-ssonalkar/Data360Accelarator.git
cd Data360Accelarator
  2. Create the settings file 
    cp .env.example .env
docker compose build
docker compose run --rm cli secret-key      # copy the printed key
    Edit .env: set CDP_ADMIN_PASSWORD, CDP_SECRET_KEY, CDP_AS_OF=today, and optionally an AI key (or add it later in Admin → AI assistant). Never commit .env.
  3. (Demo only) Load sample data 
    docker compose run --rm cli sample-data
docker compose run --rm pipeline-once
    For a real client, skip this and onboard their sources from the Admin screens instead.
  4. Start the app and the scheduler 
    docker compose up -d app scheduler
    The scheduler refreshes every CDP_REFRESH_MINUTES (default 360 = 6 hours).
  5. Put it behind HTTPS and the company loginUse the organisation's reverse proxy (Nginx, Azure Application Gateway, AWS ALB) with SSO, forwarding to port 8501.
  6. Onboard the clientFollow the Admin & onboarding guide.
Volumescdp-data holds the warehouse, uploaded files, encrypted credentials and logs; cdp-config holds clients and mappings edited in the UI. Back up both.

Command-line tool

CommandDoes
python -m cdp validateChecks all configuration and lists every problem.
python -m cdp runLoads all sources and rebuilds everything. Exit code 0 = success, 2 = partial, 1 = failed.
python -m cdp run --tenant strideLoads only one client's sources (models are rebuilt for all).
python -m cdp run --full-refreshIgnores incremental watermarks and reloads everything.
python -m cdp schedule --every-minutes 360Runs forever on a fixed interval.
python -m cdp statusShows the last runs and each source's result.
python -m cdp sample-dataCreates the demo source files.
python -m cdp secret-keyGenerates a CDP_SECRET_KEY.

Operating it

  • Monitoring: the Data pipeline page shows the last run, failing sources and data-quality results. For alerts, watch the scheduler's exit codes or the JSON log data/logs/pipeline.log (ship it to your log tool).
  • Backups: back up the data and config volumes daily. Keep CDP_SECRET_KEY in your password manager.
  • Upgrades: git pull, docker compose build, docker compose up -d. Data and configuration are on volumes, so they are kept.
  • Rolling back a configuration change: previous versions are in config/.history/; copy the file back.
  • Refresh frequency: 1–4 times a day suits most clients. Incremental sources make frequent refreshes cheap.

Common setup problems

SymptomFix
"The warehouse has not been built yet"Run the pipeline once (python -m cdp run or Run now).
Admin pages say "locked"Set CDP_ADMIN_PASSWORD and restart the app.
"Credential X is not set"Add it under Admin → Credentials, or as an environment variable.
"cannot be decrypted - was CDP_SECRET_KEY changed?"Restore the original key, or re-enter the credentials.
"…building.duckdb exists"Another refresh is running. If none is, a previous run crashed: delete that file.
ODBC error "Data source name not found"Install the database's ODBC driver and use its exact name in the connection string.
pip install times outRetry with pip install --retries 10 --timeout 60 -r requirements.txt; corporate proxies may need HTTPS_PROXY.
