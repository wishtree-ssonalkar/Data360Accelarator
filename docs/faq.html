FAQ, glossary & limitations

Answers to common questions from clients, users and delivery teams, the terms used across WishUnify, and an honest list of what it does not do yet.

FAQ: business

Is WishUnify a product we sell or a project we deliver?

It is an accelerator: a ready-made foundation that Wishtree installs and tailors for each client. The client gets a working CDP in weeks; Wishtree delivers configuration, mappings, extensions and support as services.

How long does onboarding a client take?

Typically 3–4 weeks for 4–6 systems (see the implementation playbook). A demo on the sample data takes minutes; a proof of concept with one or two real exports can take a few days.

Does the client need to buy any licences?

No platform licence. The stack is open source. Costs are the server, and optionally an AI API key from whichever provider the client already uses (Claude, Gemini, OpenAI, Azure OpenAI or an OpenAI-compatible service), charged by that provider, or a free local model via Ollama.

Can it send campaigns?

No. It builds audiences and exports them as CSV for the client's email, SMS, WhatsApp or ads tools. Direct integrations are on the roadmap.

Can we rename or white-label it?

Yes. The product name, tagline and company are set in config/platform.json (branding).

Can one installation serve several clients or brands?

Yes. Each client (or brand / business unit) has separate sources, rules and data, chosen from the sidebar. For strict separation between different companies, deploy one installation per client.

FAQ: data

What is the minimum data needed?

Orders with an id, date, value, status, channel and a customer email, phone or id. See Data requirements.

How does it know two records are the same person?

Records sharing a normalized email, a normalized phone number, or a customer id that one system stores for another are linked; each connected group is one customer. The Customer 360 "Source records" tab shows exactly which records were merged and why.

What if two people share a phone number (e.g. a family)?

They are merged into one profile, which is usually acceptable for household-level marketing. Fuzzy and household-aware matching is on the roadmap.

What if the same customer has different names in two systems?

The golden record takes each attribute from the most trusted source, set by the source's priority.

How often is data refreshed?

On a schedule (default every 6 hours on a server) or on demand with Run now. Incremental sources make frequent refreshes cheap.

Why don't the revenue numbers match our finance report exactly?

WishUnify counts completed orders only (refunded and cancelled are excluded), by order date, from the sources connected. Differences usually come from returns timing, taxes/shipping inclusion, or sources not yet connected. Reconcile during onboarding and adjust the mappings.

What happens if a source fails during a refresh?

The other sources still load, the failed one keeps its last good data, and the run is marked "partial" with the error on the Data pipeline page.

Can we delete a customer's data on request?

Remove or exclude them in the source and refresh; derived tables are rebuilt each run. For incremental database or API sources, also run a full refresh (python -m cdp run --full-refresh) so the old raw copy is replaced.

FAQ: technical & security

Where is the data stored?

In one DuckDB database file on the server (data/warehouse.duckdb), organised in Bronze, Silver, Gold and Meta layers. Uploaded files are under data/sources/. See Architecture.

How much data can it handle?

Tens of millions of rows on a single server. For more, the SQL models can be moved to Databricks, Snowflake or Fabric.

Is the app slow while data refreshes?

No. Refreshes build a separate copy and swap it in at the end; users keep seeing the previous data until then.

Which AI providers are supported?

Anthropic Claude, Google Gemini, OpenAI, Azure OpenAI, and any OpenAI-compatible service (Groq, Mistral, Together, OpenRouter, DeepSeek, or a local Ollama server for fully on-premise use). An admin picks one under Admin → AI assistant, enters the model and key, and clicks Test connection.

What does the AI assistant send to the AI provider?

Table and column descriptions, the client's category and city names, the user's question and, for the summary, up to 30 result rows. It never sends the whole database. The AI can only run read-only queries on a separate copy of one client's final tables. An admin can switch off sending result rows (Admin → AI assistant), use a local model, or leave the assistant unconfigured.

How are passwords and API tokens protected?

Encrypted at rest with a key only the server holds (CDP_SECRET_KEY); never shown in the UI again; never written into configuration files.

Who can change the configuration?

Only people with the admin password. Every change is validated, backed up and recorded with the user's name.

Does it support single sign-on?

Not built in yet. Put the app behind the organisation's SSO proxy; built-in SSO and roles are on the roadmap.

Is it tested?

Yes: an automated test suite covers file, database (incremental) and API sources, failure handling, identity matching, the golden record, configuration validation, the admin back-end and AI query safety; CI runs it on each push.

Glossary

TermMeaning
CDPCustomer Data Platform: software that unifies customer data from many systems into one profile per person.
Customer 360The complete view of one customer: details, purchases, support, behaviour and scores.
Client / tenant / business unitOne business whose data is kept separate inside WishUnify.
SourceOne connected system or data feed of a client (e.g. "erp_orders").
Mapping (source type)Rules that turn one kind of system's columns into the standard model; reusable across clients.
Standard modelThe six common entities every source is mapped to: customers, orders, order lines, products, events, tickets.
Identity resolutionDeciding which records from different systems belong to the same person.
NamespaceA short name for a system's customer ids, so another system's references to those ids can be linked.
Golden recordThe single best version of a customer's details, picked from the most trusted sources.
Bronze / Silver / GoldData layers: raw copy → cleaned and unified → final calculated tables.
RFMRecency, Frequency, Monetary: three 1–5 scores for how recently, how often and how much a customer buys.
SegmentA named group from RFM scores (Champion, Loyal, At Risk…).
TierPlatinum / Gold / Silver / Bronze by lifetime spend.
Lifecycle stageProspect, New, Active, Lapsing, Churned.
Churn riskLikelihood a customer has stopped buying (High / Medium / Low).
CohortCustomers who made their first purchase in the same month.
Retention rateShare of a cohort that bought again in a later month.
AOVAverage order value = revenue ÷ orders.
CSATCustomer satisfaction score (1–5) from support.
FunnelSteps from visit to purchase and how many visitors reach each.
Incremental loadFetching only rows added or changed since the last refresh.
WatermarkThe last value read from the incremental column, remembered for the next refresh.
As-of dateThe date used as "today" for recency calculations.
Data-quality checkAn automatic test of the loaded data (e.g. every order has a valid status).

Roadmap

  • Security: built-in SSO (Microsoft Entra ID / Google) with roles: admin, analyst, marketing, viewer; per-client access.
  • Identity: fuzzy name and address matching; household grouping; manual merge / split.
  • Activation: push audiences to email/SMS/WhatsApp platforms and ad networks (Meta, Google).
  • Prediction: machine-learning churn probability, customer lifetime value forecast, next-best-product.
  • Connectors: native Shopify, Salesforce, HubSpot, Zendesk / Freshdesk API connectors; SFTP.
  • Scale: Databricks / Snowflake / Fabric deployment option using the same SQL models.
  • Model: subscription, loyalty-points and booking entities for more industries.
