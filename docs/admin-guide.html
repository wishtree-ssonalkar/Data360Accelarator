Signing in

The Admin section at the bottom of the menu has five screens: Clients, Sources & connections, Mappings, AI assistant, and Credentials & history. They ask for the admin password (set by IT as CDP_ADMIN_PASSWORD) and your name, which is recorded in the change history. After 5 wrong attempts sign-in is locked for 5 minutes. Use Sign out of admin in the sidebar when you are done.

Development modeOn a laptop without a password, admin screens open with a yellow warning. Deployed servers run with CDP_ENV=production and stay locked until a password is set.

2. Store credentials

Admin → Credentials & history. Enter a Name in capitals (e.g. ACME_ERP_DB) and the Value (connection string, password or token), then Save credential.

  • Values are encrypted and never shown again; to change one, save the same name with a new value.
  • The table shows every credential used by any source and whether it is stored, set as an environment variable, or MISSING.
  • Connection string formats:

3. Map a new system

Skip this step when a mapping for the system already exists (Shopify, Salesforce contacts, POS lines, Zendesk, JSON web events, product catalog, and the six Standard template mappings). Mappings are reusable across clients.

Admin → Mappings → "➕ New mapping".

  1. Name itMapping id (lowercase, e.g. acme_erp_orders), system name (e.g. "Acme ERP") and a description.
  2. Load sample dataUpload a sample file, or read a few hundred rows from a source already configured.
  3. Add what the data containsChoose the entity (customers, orders, order_lines, products, events, tickets) and click Add. One source can feed several entities, e.g. a POS export with one row per item → orders and order_lines.
  4. Map each columnFor each standard column, pick the matching source column from the dropdown. Common names (email, mobile, order_no, qty…) are matched automatically. Use or SQL expression when a value needs converting (see the cookbook below). Rows marked req. must be filled.
  5. Set linking optionsId namespace (customers): a short name for this system's customer ids. Customer ids belong to namespace (orders, events, tickets): the namespace of the customer system those ids point to. One row per (group by): only for line-level data that must become one row per order.
  6. Check the resultThe preview shows the mapped rows from the sample and any error. Fix until there are no warnings.
  7. Save mappingIt is now available when adding sources.

Mapping expression cookbook

Expressions are DuckDB SQL over the source columns (which arrive as text). Put column names with spaces or capitals in double quotes, e.g. "Order Date".

Date in dd/mm/yyyystrptime("OrderDate", '%d/%m/%Y')

Unix secondsto_timestamp(CAST(ts AS BIGINT))

Status from wordsCASE lower(state) WHEN 'delivered' THEN 'completed' WHEN 'returned' THEN 'refunded' ELSE 'cancelled' END

4. Connect sources

Admin → Sources & connections, choose the client, then "➕ New source".

  1. Name and mappingSource name (e.g. erp_orders) and "What kind of data is it?" (the mapping). For customer sources, set Golden-record priority: 1 = most trusted for names and contact details.
  2. ConnectionChoose one of the options below.
  3. Test connectionShows "Connected. Read N sample rows", the Raw sample and the result After mapping (including which standard columns came out empty). If the mapping doesn't fit, choose another mapping or fix it under Mappings.
  4. Save sourceIt is loaded on the next refresh.
ConnectionFieldsExample
File · UploadFormat, files. Each upload is added to the source's folder; uploading the same file name replaces it.Monthly CSV exports from the billing system.
File · Path / cloud URLPath or pattern relative to the client folder, or a cloud URL. Optional delimiter or sheet name.orders/*.csv · s3://acme-exports/crm/*.parquet · az://exports/pos/*.csv
DatabaseDatabase type, connection-string credential, table or SQL query, optional incremental column.SQL Server · ACME_ERP_DB · sales.orders · incremental modified_at
REST APIURL, authentication (bearer token or API-key header + credential), records path, paging, optional incremental parameter.https://api.helpdesk.com/v2/tickets · records path data.tickets · page size 100
Incremental loadsFor large database tables, set an incremental column that increases when a row changes (e.g. modified_at). Each refresh then fetches only new and changed rows; the latest version of each row wins.

5. Load the data

Go to Data pipeline and click Run now. The button shows "Refresh running…" with the latest progress line; when it finishes, the page reloads with the new data. Dashboards keep showing the previous data while a refresh runs. Scheduled refreshes also run automatically on the server.

6. Verify

  • Data pipeline → Sources: every source "success", with plausible row counts.
  • Data quality: all checks pass, or warnings are understood (e.g. low "orders linked to a customer" means orders lack email/phone/id).
  • Identity resolution: the share of duplicates merged looks plausible; check "How profiles were matched".
  • Customer 360: search 3–5 customers the client knows well and confirm orders and spend with them.
  • Executive overview: reconcile last-12-months revenue with the client's finance figure (expect small differences for refunds/cancellations and timing).

Set up the AI assistant

Admin → AI assistant. Use whichever AI service the organisation already has a key for.

  1. Choose the providerAnthropic Claude, Google Gemini, OpenAI, Azure OpenAI, or OpenAI-compatible.
  2. Fill in the detailsSee the table below. The key is stored encrypted under the credential name shown (e.g. OPENAI_API_KEY) and never displayed again; leave the key box blank to keep the current one.
  3. Privacy settingAllow sending result rows to the AI provider for summaries: when off, only table descriptions and the question are sent, and answers come without a written summary.
  4. Test connectionSends a tiny request and confirms the model answers correctly.
  5. Save"Ask your data" now uses this provider; its sidebar shows the provider and model in use.

Changes, history and rollback

  • Every save is checked against the whole configuration first; if anything is wrong, nothing is saved and every problem is listed.
  • The previous version of every changed file is kept in config/.history/; IT can copy it back to roll back.
  • Credentials & history → Change history shows who changed what and when.
  • Changes take effect on the next refresh. Removing a source or client removes its data from dashboards after the next refresh; uploaded files are kept.

Troubleshooting sources

Error / symptomCause and fix
File not found / No files matchWrong path or nothing uploaded yet. Paths are relative to the client's folder.
Credential X is not setStore it under Credentials (exact same name).
ODBC error … login failed / timeoutWrong user/password, firewall closed, or wrong server name. Test with the client's DBA.
REST call failed … 401 / 403Token wrong or expired, or missing read scope.
Mapping … failed: column "X" not foundThe source's column names changed. Update the mapping (Mappings → load sample → re-pick).
must appear in the GROUP BY clauseA grouped mapping uses a plain column; wrap it in any_value(...), min(...) or sum(...).
Status "warning": source returned 0 rowsThe export was empty; previous data is kept. Check the source system.
Data quality: "Order status values are valid" below 100%The status mapping leaves unknown values; extend the CASE expression.
Many single-source profiles / duplicatesSystems don't share email or phone. Map more contact fields, or a shared customer id via namespaces.

Implementation playbook

For Wishtree delivery teams. Typical timeline for a client with 4–6 systems:

WeekActivitiesOutcome
Week 1: DiscoverWorkshop on goals and KPIs; list systems; agree business rules; data-protection approval; request access and samples.Source inventory, rules, access requests raised.
Week 1–2: Set upDeploy server (Docker), HTTPS + login, admin password and secret key; create the client.Environment ready.
Week 2–3: ConnectStore credentials; build mappings for new systems; connect and test each source; first full load.All sources loading.
Week 3: ValidateData-quality review; reconcile revenue and customer counts with the client; tune rules and priorities.Numbers signed off.
Week 4: Go liveSchedule refreshes; user training (User guide); hand over Admin guide; set up monitoring and backups.Client using it.

Go-live checklist

  • ☐ CDP_ADMIN_PASSWORD, CDP_SECRET_KEY set; secret key stored in the password manager
  • ☐ CDP_AS_OF=today (not the sample date)
  • ☐ HTTPS and company login in front of the app
  • ☐ All sources "success"; data-quality checks pass or are signed off
  • ☐ Revenue and customer counts reconciled with the client
  • ☐ Scheduler running at the agreed frequency; failure alerts in place
  • ☐ Daily backups of the data and config volumes
  • ☐ AI assistant: provider chosen and tested in Admin → AI assistant, result-row sharing set per the client's policy (or left unconfigured)
  • ☐ Sample clients (Stride, UrbanLeaf) and any test clients removed
  • ☐ Users trained; admin guide handed over

Doing it with files instead

Everything above is stored as JSON files in config/ and can also be edited directly, for automation or version control. See docs/ONBOARDING.md in the repository for the file formats, then run python -m cdp validate and python -m cdp run.
